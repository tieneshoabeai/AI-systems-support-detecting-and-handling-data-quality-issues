Dòng Chảy Dữ Liệu 2 Chiều

Request Flow (Downstream):
User Click → Hook Trigger → Service DTO → Axios Instance → Network.

Response Flow (Upstream):
Network → Unwrap Envelope → Runtime Validation → Store Update → UI Re-render.

CHƯƠNG 3 · QUẢN LÝ VÒNG ĐỜI

Composition Root & Vòng Đời AppRuntime: Cơ Chế retain / release

Cơ Chế Khóa Vòng Đời (Lifecycle Lock)

Trong React 19, StrictMode sẽ thực hiện unmount và mount lại component ngay trong một microtask turn. Cơ chế retain() đếm số owners đang gắn kết:

retain: () => {
  owners += 1;
  return () => {
    owners -= 1;
    queueMicrotask(() => { if (owners === 0) dispose(); });
  };
}
Ưu Điểm Kiến Trúc
  • Chống rò rỉ tài nguyên: Chỉ đóng database và hủy coordinator khi toàn bộ tab/component đã giải phóng.
  • Không tự chạy khi import: Việc import module app/index.ts tuyệt đối không tự boot ứng dụng hay tạo instance ngầm.
  • Độc lập kiểm thử: Dễ dàng tạo instance runtime giả lập độc lập trong môi trường Vitest.

CHƯƠNG 4 · BẢO MẬT PHIÊN

Cơ Chế Lưu Trữ Token An Toàn Trong sessionStorage

Cấu Trúc Khối Dữ Liệu StoredSession
// Khóa lưu: 'data-quality.auth.v1'
{
  "schemaVersion": 1,
  "accountId": "user-uuid-1234",
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "def50200..."
}

Chỉ lưu các trường đã whitelist; không lưu mật khẩu, role hay các thuộc tính mutable vào storage.

Tại Sao Không Dùng HttpOnly Cookie?
  • Cách ly theo từng tab trình duyệt: sessionStorage tự động cô lập phiên giữa các tab khác nhau, hỗ trợ đa tài khoản độc lập.
  • Loại bỏ triệt để CSRF: Request bắt buộc phải gắn Authorization: Bearer <token> qua code, hacker không thể kích hoạt request tự động qua form ẩn.
  • Tự động thu hồi khi đóng tab: Token sẽ tự hủy khi người dùng tắt trình duyệt mà không cần can thiệp.

CHƯƠNG 5 · LUỒNG NGHIỆP VỤ

Luồng Quản Lý Workspace & Kiểm Soát Xung Đột Phiên Bản (Version)

Các Thao Tác Đã Kết Nối API Thật
  • GET /workspaces: Lấy danh sách kèm phân trang con trỏ.
  • POST /workspaces: Tạo không gian mới kèm cấu hình dung lượng.
  • PATCH /workspaces/{id}: Cập nhật tên/mô tả kèm kiểm tra version.
  • DELETE /workspaces/{id}: Xóa không gian làm việc.
  • POST /workspaces/{id}/transfer-owner: Bàn giao quyền sở hữu.
Cơ Chế Khóa Lạc Quan (Optimistic Lock)

Mỗi workspace có một thuộc tính version: number. Khi thực hiện cập nhật:

PATCH /workspaces/{id}
Body: { name, description, expectedVersion: 2 }

Nếu phiên bản trên server đã bị người khác thay đổi (version !== 2), API trả về lỗi 409 Conflict, Frontend lập tức báo người dùng tải lại dữ liệu mới nhất.

Phân Trang Con Trỏ (Cursor Pagination)

Thay vì dùng offset làm chậm cơ sở dữ liệu lớn, API sử dụng con trỏ nextCursor:

POST /datasets/{id}/records/query
Body: { limit: 50, cursor: "cur_eyJpZCI..." }
Response: { items: [...], meta: { hasMore: true, nextCursor: "cur_..." } }
Tối Ưu Render Virtual Scrolling
  • Chỉ vẽ DOM hiển thị trong khung nhìn: DOM chỉ duy trì khoảng 30–40 dòng cùng lúc.
  • Bộ nhớ tab ổn định: Duy trì mức tiêu thụ RAM dưới 80MB ngay cả khi lướt file 500,000 dòng.
  • Hỗ trợ Sort & Filter trực tiếp: Đẩy điều kiện lọc xuống backend xử lý qua request payload.

CHƯƠNG 6 · KIỂM SOÁT LỖI

Chiến Lược Chuẩn Hóa & Kiểm Soát Lỗi Hệ Thống Toàn Diện

Chuẩn Hóa Mã Lỗi HTTP Phổ Biến
  • 400 Bad Request: Hiển thị thông điệp xác thực form cụ thể.
  • 401 Unauthorized: Kích hoạt quy trình kiểm tra và gia hạn token.
  • 403 Forbidden: Thông báo thiếu quyền thao tác trên tài nguyên.
  • 404 Not Found: Điều hướng sang trang NotFoundPage an toàn.
  • 409 Conflict: Cảnh báo dữ liệu đã bị sửa đổi ở phiên khác.
  • 500+ / Outage: Chuyển sang phase local-limited nếu còn hạn token.
Nguyên Tắc Retry An Toàn

GET Requests (Idempotent): Cho phép người dùng bấm Retry hoặc tự động retry tối đa 1 lần nếu gặp lỗi mạng chập chờn.

Mutation Requests (POST / PATCH / DELETE): TUYỆT ĐỐI KHÔNG TỰ ĐỘNG RETRY để ngăn chặn việc tạo trùng lặp bản ghi, trừ trường hợp Refresh Token được Coordinator retry có kiểm soát.
